Medallion Architecture
Copy section link ↗
Summary

A practical MySQL implementation of the Medallion Architecture pattern for an e-commerce data pipeline, moving data through Bronze, Silver, Gold, and Rejects layers.

Architecture
Bronze · raw → Silver · cleaned → Gold · analytics↘Rejects · quality monitoring
Implementation

Completed all four main Bronze tables—Orders, Customers, Products, and Order Items—along with matching Silver transformations, validation, and rejection handling. The Gold layer includes customer, product, order, time-series, and sales fact tables.

Data quality

Invalid order and customer records are captured in Rejects tables during transformation. Products and Order Items do not use separate reject tables.

Relationships

Foreign keys preserve referential integrity across customers, orders, order items, and products. Composite keys include the source system, supporting one-to-many customer and order relationships and many-to-one product references.

Development environment

MySQL Workbench 8.0+ with a testing database, developed in VS Code using a SQL Connector Tool extension.

Platinum Fire
Copy section link ↗
Summary

Platinum Fire is an open-source Python tool that helps analysts, business users, and anyone quickly identify and transform values in their data through a simple GUI—no coding required.

Problem

Messy datasets often contain inconsistent column names, mixed date formats, phone numbers, state codes, incorrect data types, and inconsistent text formatting. Cleaning those values manually or with one-off scripts can take hours.

Implementation

A Tkinter-based desktop application that lets users upload files, inspect their structure and data types, apply pre-built transformations, and save cleaned datasets back to the data folder.

Capabilities
  • Supports CSV, Excel, JSON, and Parquet files.
  • Standardizes column names, names, dates, state values, numeric values, phone numbers, percentages, currency, and IDs.
  • Includes Light, Dark, and Warm Tones themes.

Crime Data ETL
Copy section link ↗
Summary

Developed a full end-to-end ETL pipeline and interactive Tableau dashboard to analyze over 3.5 million crime records across Colorado from 2016 to 2023. This project involved cleaning and transforming raw public data using Python (pandas, numpy, scikit-learn), imputing missing values with advanced techniques like multiple imputation, and loading the data into a MySQL database for structured analysis.

Problem

Public crime records need cleaning and a consistent structure before analysis.

Architecture
Public records → Python transforms → MySQL → Tableau
Implementation

Cleaned and transformed records with pandas, NumPy, and scikit-learn, including multiple imputation for missing values.

Engineering decisions

Separating transformation, storage, and visualization supports structured analysis of the cleaned records.

Impact

An end-to-end pipeline and interactive dashboard covering more than 3.5 million Colorado crime records from 2016–2023.

Technologies

Python · pandas · NumPy · scikit-learn · MySQL · Tableau
